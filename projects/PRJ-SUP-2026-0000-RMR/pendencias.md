# 🎯 Hub de Pendências — registro único

> **Fonte única de acompanhamento** de tudo que precisa de resposta (PM/PO/Managers). Regra: o **detalhe fica onde o contexto vive** (feature card, checklist, LLD) — aqui fica **só a linha de controle** (aponta, não copia).
>
> 📊 **Relatório de urgência:** rode `scripts/check-pendencias.sh` (compara os prazos com a data de hoje e lista 🟥 vencidas / 🟠 vencendo).

## Como funciona

| Regra | Detalhe |
|---|---|
| **ID** | `PENDENCY-NNNN` — numeração global sequencial; citar o ID no doc de origem (feature card §6, checklist, etc.) |
| **Origem** | link para o documento onde vive o detalhe (pergunta, contexto, decisão) |
| **Dono** | quem responde — **obrigatório** (área ou pessoa) |
| **Prazo** | data ISO `AAAA-MM-DD` — **obrigatório para pendência aberta**; textos como `pós-Onda 1-Must (MVP mínimo)` só em itens **❌ Adiadas** |
| **Status** | ⬜ Aberta · ⏳ Em resposta · ✅ Respondida · ❌ Adiada (com nova data/reason) |
| **Ciclo de vida** | respondida → detalhe é atualizado no doc de origem → linha vira ✅ e sai do relatório |

**Ritual sugerido:** 15 min/semana — rodar o script, resolver 🟥/🟠 primeiro. Pendência que **bloqueia a Onda 1-Must (MVP mínimo)** tem prazo antes do início da Sprint 1.

- ✅ **Lei de formação dos identificadores — PENDENCY-0012 (2026-10-21, 6/6):** (1) NDS = **atributo de importação opcional** (doc revisado) · (2) **GPON unificado** em um único arquivo (whitelist de 7 fabricantes, regex 12/16) · (3) **precedência:** a regra específica do **modelo/tipo/família vence a genérica** (celular 10–12 · decodificador 10–14 · roteador 11–14) · (4) **mapeamento MODELO → identificadores definido** — tabelas dedicadas `TIPO_IDENTIFICADOR` + `MODELO_IDENTIFICADOR` (com **primário** por modelo → `ATIVO.identificador_unico`; DDL no rolling wave da FEATURE-0001.0003) · (5) **`MAC_ADDRESS` = exigência de cross-validation** (não é identificador §5.1 nem atributo §5.2) · (6) **SMART_CARD = só regex de 12 dígitos**.
